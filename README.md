# 用 Steam 標籤把你的遊戲定位想清楚

單檔離線網頁工具。用 430 個 Steam 官方標籤釐清遊戲定位，標出「已確定」「差異化」「還沒決定」，並把還沒決定的附上**取捨後果**讓你自己判斷。給遊戲企劃課學生與獨立開發者用。

**這個工具不會幫你生成遊戲。** 它幫你想清楚方向，然後給你兩種產出：

| 產出 | 給誰看 | 用途 |
|---|---|---|
| 📋 **定位單** | 給人看 | 陳述句寫成，可直接當企劃初稿、課堂作業繳交，或貼進其他文件 |
| 🤖 **AI 工單** | 給 AI 看 | 複製後貼給任何 AI，才會得到一頁企劃、可玩雛型、商店頁文案那些成品 |

標籤選擇、抽籤、取捨說明、兩種產出的組裝，全部在你的瀏覽器離線完成，不連網也不呼叫 AI。

**線上直接用**：https://treefar.link/tool　（完整網址 https://treefar.link/steam-tag-prompter/ ）

不需安裝、不需帳號。全部運算在瀏覽器本機完成，不會上傳任何資料；你的選擇存在自己瀏覽器的 localStorage 裡。

市場查證（有沒有人做過同樣的東西）見 [MARKET-CHECK.md](MARKET-CHECK.md)。

## 使用方式

點上面的線上網址，或把 `index.html` 下載後雙擊開啟（任何瀏覽器皆可，離線可用，選擇會自動存在瀏覽器裡）。

1. 三種入口任選：**🎲 靈感輪盤**抽一組當命題、**快速起手式**套 14 組常用組合、或直接點標籤。
2. 點標籤選方向。同一顆標籤重複點會循環角色：**核心**（藍）→ **差異化**（綠）→ **待抉擇**（黃）→ 取消。
3. 標成「待抉擇」的標籤若構成一組已知抉擇（例如 Roguelike vs Roguelite），右側會**直接展開取捨後果**——選 A 會怎樣、選 B 會怎樣，講的是玩法與開發成本，不是詞義解釋。**這一段不需要 AI**，工具自己就會告訴你。
4. 填一句話構想（可留白）、選製作時間（48 小時／一學期／一學年／一年半／不限）與團隊人數（1～5 人）。
5. 按 **📋 產生定位單** 得到給人看的版本；需要 AI 產出成品時，再勾選要請 AI 做哪些交付物（A～E），按 **🤖 產生 AI 工單** 並把全文貼給 AI。

工單的兩種對象模式：**一般模式**餵給任何 AI，工單自帶標籤說明；**進階管線模式**只改寫工單的角色設定段，要求 AI 一律查自有 Unity 資產庫索引、不得憑記憶推薦套件。沒有這種索引就用一般模式。

## 靈感輪盤

抽一組標籤當命題，三種模式：

| 模式 | 行為 |
|---|---|
| 🎯 保證可做 | 補齊視角、美術風格、單多人三個必要維度與一個類型訊號，自動避開 46 組互斥關係與多人重工程標籤，並從 32 組**附取捨說明**的配對中留一組待抉擇（如 Roguelike vs Roguelite、First-Person vs Third Person） |
| 🌀 完全隨機 | 不管維度也不管矛盾，抽到什麼算什麼。抽出無法並存的組合是正常的，那正是發想起點 |
| 💥 刻意衝突 | 從 42 組反差配對表挑一組罕見組合當差異化核心（Cooking×Souls-like、City Builder×Horror、Incremental×Psychological Horror），其餘照「保證可做」規則補齊 |

抽到的「待抉擇」組會在右側直接展開取捨後果，**這一段不需要 AI**。

## 📖 遊戲製作與選標籤指南

頁首右上有一顆「遊戲製作與選標籤指南」，開啟的說明頁涵蓋六節，內容跟工具一樣是離線的（就在同一個檔案裡）：

1. **先想清楚 MVP**——MVP 不是「功能少的完整遊戲」而是「能驗證核心樂趣的最小切片」；垂直切片 vs 水平切片；正確的開發順序（核心動詞 → 能玩的循環 → 失敗與重來 → 最後才是包裝）
2. **標籤不是愈多愈好**——Steam 給 20 個但只有前 5 個是門面；掛名不符實會把你推給錯的受眾而換來差評；建議配比
3. **人數也不是愈多愈好**——溝通路徑是 `n(n-1)/2`，1 人 0 條、5 人 10 條；四人以上必須有版本控制、明確分工、固定同步，否則會退化成「1 人在做 ＋ 4 人在等」
4. **時間對應的合理範疇**——48 小時／一學期／一學年／一年半各自做得到什麼
5. **十大維度各自在問什麼**——每個維度的核心問題，附代表作幫你理解那個標籤是什麼感覺
6. **常見錯誤**——七項對照表

## Steam 上像哪些遊戲？

選完標籤，右側面板的「Steam 上像哪些遊戲？」會顯示有幾款相符，點開是一整面卡片：官方縮圖、繁中簡介、發行年、所有語言總評論數、命中與落空的標籤、吻合百分比，點卡片直接開 Steam 商店頁。

**完全吻合不保證存在，所以一律列最接近的。** 點超過四個標籤時，Steam 商店搜尋本身也常常回 0 筆——那是 AND 邏輯。這裡改用加權分數排序：核心 3 分、差異化 2 分、待抉擇 1 分，卡片上劃掉的標籤就是那款遊戲沒有的。一個標籤都沒共通的不列入，因為那不叫「接近」。

資料是**建置時抓好的離線快取**，開啟本頁時完全不連網。原因有兩個：

1. Steam 的 store API 不回 `Access-Control-Allow-Origin`（2026-09-16 實測），瀏覽器直接 `fetch` 一定被 CORS 擋。
2. 這個工具要能離線雙擊執行，執行期不該依賴任何伺服器。

抓取腳本是 `build-game-index.js`：

```bash
node build-game-index.js --store            # 完整跑（約 6 小時，每階段都存檔，可中斷）
node build-game-index.js --resume --store   # 中斷後續跑：沿用候選池，只補缺的
node build-game-index.js --select           # 不連網，只用既有快取重新挑選與輸出
```

流程（2026-09-17 改版）：

1. **候選池**：430 個標籤各抓「相關性前 25 名」與「全球熱銷前 400 名」，約 9900 款。只抓相關性時偏新作，DARK SOULS III、Don't Starve 這類老經典連候選池都進不去。
2. **初篩 6000 款**：每個標籤保障熱銷前 10 名，其餘依最佳熱銷名次補滿。
3. **查真實評論數**：每款打一次評論 API（`/appreviews/<appid>?language=all`），取所有語言的總評論數。
   **搜尋列表與商店頁上的評論數都按瀏覽者語言篩過**，不能用（實測 Hades 商店頁 142,444、實際 308,520；Monster Train 搜尋列表 331、實際 22,948）。
   連續 20 款查不到視為斷網，暫停 2 分鐘；整輪跑完失敗的重查，最多 3 輪；仍有超過 1% 查不到就中止，不拿殘缺資料決選。
4. **決選 3000 款**：每個標籤保障評論數最多的 5 款，其餘依評論數補滿。已知收不進來的（非遊戲、軟體、人工排除）先拿掉再決選，遞補的抓完明細再檢查，最多 3 輪。
5. **明細**：逐款用 `appdetails` 補名稱、簡介、縮圖、年份與發行商類別。
6. **商店頁完整標籤**：逐款抓商店頁的玩家標籤（通常 20 個，含票數），卡片上的標籤依票數排序。搜尋列表只給前幾名標籤，改版前第 7～12 高票標籤只記到 31%。
7. **手動補收**：`data/game-include.json` 列的名作不佔 3000 款名額，照樣過明細判定與排除清單。每筆寫理由與來源，appid 要上 Steam 查證過。新增後要帶 `--store` 跑一次才抓得到標籤。
8. **標籤總遊戲數**：每個標籤在 Steam 上有幾款，給冷門標籤判定用。

**已知漏洞**：熱銷榜依營收排，免費遊戲進不來；評論數偏少的名作也可能落選。評測時評審提名、確認漏收的 10 款（Doki Doki Literature Club!、CLANNAD、Amnesia: The Dark Descent 等）已放進手動補收清單，索引共 3010 款。

**罕見組合提示**：最接近的遊戲吻合率低於 65% 時，卡片上方會提示，並列出從未同時出現的標籤組合與本身就少見的標籤。提示只陳述事實，並提醒兩種可能：還沒人做過的方向，或市場很小。

門檻是 2026-09-17 看評測結果定的：20 題裡評審評最差的 3 題全被標到，14 組起手式都不會被標。已知代價是選的標籤越多越容易被標（隨機抽 8 個標籤約 8 成會跳提示）。原本用「跟同樣標籤數的隨機組合比，落在最低 20%」，但隨機組合本來就冷門，最差的 3 題只標到 1 題，已改掉。門檻在 `core.js` 的 `LOW_SCORE`，測試用評測題目鎖住校準。

三個實測到的限制（會變，變了就改 `build-game-index.js` 的檔頭註解）：

- `appdetails` **一次只吃一個 appid**，傳多個回 `null`，`filters` 參數也不生效——所以只能一款一款抓，速率抓每 1.6 秒一次。
- `movies` 欄位**已經沒有 `mp4` / `webm` 直連**，只剩 DASH 與 HLS 串流網址。所以卡片只放預告片的封面幀，影片本身請到商店頁看。
- 圖片網址**不能用 appid 推導**。Steam 已改成含內容雜湊的路徑（`.../apps/<appid>/<40位雜湊>/header.jpg`），連檔名都會變（某些遊戲是 `header_alt_assets_9_tchinese.jpg`）。舊式 `.../apps/<appid>/header.jpg` 只有 2023 年以前的舊作還通。資料檔存的是 API 回的實際網址，只砍掉共同前綴與 `?t=` 參數。

簡介以 `l=tchinese` 取得，Steam 沒提供該語言的款別會是英文原文。

**過濾分兩層：**

1. **自動規則**（`steam-filters.js`，爬蟲與測試共用同一份）：type 不是 game、發行商類別屬軟體、沒有可用圖片。軟體判別看 `genres` 不看 type 與標籤，25 筆實測樣本鎖在 `tests/steam-filters.test.js`。
2. **人工排除清單**（`data/game-exclude.json`）：自動規則擋不到、但不是遊戲的——瞄準訓練與游標工具、跑分展示、VR／360 影片。每筆要寫理由，改完跑 `node build-game-index.js --select` 不連網就能套用。

**收錄方針（2026-09-17 定案）：工具忠於 Steam，不以成人與否過濾。** 上課不刻意提，也不刻意迴避。所以沒有 18 禁過濾、沒有成人向黑名單，`tests/steam-filters.test.js` 有一條測試把這個方針鎖住。頁面上給學生看的說明只寫「已濾除非遊戲項目」，不特別提成人。靈感輪盤的禁抽清單仍不會**隨機抽出** Sexual Content、Nudity、Hentai 等標籤，但學生自己點選或搜尋都選得到。

**備查**：2026-09-16 曾實測 Steam 匿名 appdetails 分不出成人向作品（NUKITASHI、Tentacle Locker 2 上架的是全年齡版，年齡與描述子跟 Hades 相同），玩家標籤也不可靠（漫威爭鋒、蔚藍檔案、Muse Dash 都被惡搞掛過 Hentai）。若日後方針改變要過濾，這兩條路都已證實走不通。

## 十大維度覆蓋概覽

不管是抽籤、套起手式、手動點選還是貼短碼還原，輪盤下方都會顯示十個維度的狀態：

- **已填的**顯示抽到什麼標籤（含待抉擇組會標黃）
- **還沒填的**分兩種：類型、視角、美術風格、玩家結構缺了會標紅「必補」（缺了無法定位）；題材、情緒、敘事、機制、範疇標灰「選配」（加分項）
- 大類型與子類型是同一個問題的兩種答法，其中一邊有了另一邊就顯示「—」不算缺
- 點任一格會捲到該維度去補（該維度被搜尋或精選模式藏起來時會自動展開）

另外，**與已選標籤互斥的標籤會變灰不可點**並劃線，滑鼠停上去說明是被誰擋的（例如選了 2D，3D 與 VR 就會鎖住）。取消原標籤就自動解鎖；已經選中的標籤永遠不鎖，否則會取消不掉。

**🔒 鎖定重抽**：喜歡的標籤按鎖頭固定，再按同一顆按鈕只重抽沒鎖的，可逐步收斂。
**🔗 組合短碼**：每組產生 `S2…` 短碼，貼回工具即還原。可發全班同一題，或讓學生交作業時附碼驗證。
**🕘 抽籤歷史**：保留最近 10 組可還原。

非遊戲軟體類（Photo Editing、Benchmark 等）與成人內容標籤在所有抽籤模式都不抽。

## 標籤庫

共 430 個標籤，**全部都是 Steam 官方標籤**，任何一個都能直接掛到商店頁。預設只顯示 233 個定位常用的，勾「顯示全部官方標籤」展開全部；搜尋一律搜全庫。頁面底部的數字由程式從資料算出，跑過 `--fetch` 後會自動跟著變。

本工具刻意**不收官方清單以外的社群慣用詞**。理由是 Steam 是權威，掛不上去的標籤放在選單裡只會讓人誤點。那些說法沒有消失，而是寫進最接近的官方標籤說明裡——搜「低多邊形」或「Low Poly」會找到官方的 `Stylized`，搜「技能樹」會找到 `Character Customization`。官方真的沒有的美術或機制細節，寫在「一句話構想」欄或工單的提示詞段落即可，一樣傳達得到 AI。

| 來源 | 筆數 | 說明 |
|---|---|---|
| Steam 官方熱門標籤清單 | 430 | `store.steampowered.com/tagdata/populartags/{english,tchinese}`。中文為 Valve 官方繁中譯名，附官方 tagid。抓取日期見 `data/raw/SOURCE.md` |
| 其中標為「定位常用」 | 233 | 附維度分類、🔥🎯⚠️ 標記與白話說明。社群同義詞（Monster Tamer、MMO、Photorealistic 等 15 個）已對齊到官方名 |
| 官方清單以外的標籤 | 0 | 完全對應 Steam，由測試釘住。社群慣用詞掛在最接近的官方標籤說明裡供搜尋 |

標籤說明文字為教學用途，非 Valve 官方定義。

`data/raw/` 下的 Steam 標籤原始資料取自 Valve 的公開端點，著作權屬 Valve Corporation，本專案僅為建置需要而收錄。Steam 與 Valve 商標屬 Valve Corporation 所有；本專案與 Valve 無隸屬或背書關係。

## 更新標籤庫

Steam 標籤清單會變動，重跑即可：

```bash
node build-tags.js --fetch
```

腳本會抓官方最新清單（先驗證再覆蓋，抓取失敗不會毀掉舊資料）、與 `data/curated-tags.json` 合併、依 `data/official-dims.json` 歸類，再把標籤表與 `core.js` 注入 `index.html`，並更新 `data/raw/SOURCE.md` 的抓取日期。

官方新增而未歸類的標籤會自動落到維度 10 並標「未分類官方標籤」，補進 `official-dims.json` 即可。**同義詞不要新增成獨立標籤**（否則使用者會以為官方沒有這個標籤）：同一概念只是名字不同就加進 `build-tags.js` 的 `ALIAS` 指向官方名；官方真的沒有的缺口就不要收，把說法寫進 `build-tags.js` 的 `VOCAB`，它會掛到最接近的官方標籤說明上供搜尋。**改 `ALIAS` 時記得檢查 `core.js` 的 `CLASH`／`ASK_PAIRS` 有沒有引用舊名**，否則那組配對會永遠選不到。改完跑 `npm test`。

| `data/game-index.json` | 3000 款遊戲的標籤（依票數）、簡介、縮圖、評論數，與罕見度門檻 | **不要，是抓取產物** |
| `data/raw/game-pool.json` | 標籤爬取階段的候選池，供 `--select` 重算 | 不要 |
| `data/raw/review-counts.json` | 初篩 6000 款的所有語言總評論數 | 不要 |
| `data/raw/tag-totals.json` | 每個標籤在 Steam 上的總遊戲數 | 不要 |
| `data/raw/game-details-cache.json` | 逐款明細與商店頁標籤快取，讓重跑不必整份重抓 | 不要 |
| `tests/core.test.js` | `core.js` 與標籤資料的回歸測試 | 可 |
| `tests/games.test.js` | 參考遊戲配對與索引資料的回歸測試 | 可 |
| `tests/steam-filters.test.js` | 過濾規則的回歸測試（含 25 筆實測類別樣本） | 可 |
| `MARKET-CHECK.md` | 同類工具市場查證 | 可 |
| `LICENSE` | MIT，另註明 Steam 資料的授權範圍 | 可 |

`index.html` 是單檔的原因是要能離線雙擊執行，所以 `core.js` 與標籤表都由建置腳本內嵌進去。
**改邏輯改 `core.js`，改標籤改 `data/*.json`，然後跑 `npm run build`**——直接改 `index.html` 會在下次建置時被蓋掉，CI 也會擋下來。

## 開發

```bash
npm test               # 跑回歸測試（不需瀏覽器）
node verify-games.js   # 代表作逐款到 Steam 查證 appid 與標題
npm run build:games    # 重抓參考遊戲索引（約 85 分鐘；中斷後用 node build-game-index.js --resume 續跑）
npm run build          # 重新建置 index.html
npm run verify         # 建置後跑測試
```

測試用可注入的偽隨機源，所以「500 次抽籤都不出現互斥標籤」這種性質可以穩定重跑，失敗時輸出會附 seed 供重現。CI（GitHub Actions）在每次 push 與 PR 跑測試，並檢查 `index.html` 與 `data/tags.json` 是不是最新的建置結果。
